## 2. 목표와 작업 순서

### A. 데이터 공급자와 운영 환경 확정

1. 기존 계정·로그인·설정 중 사용할 수 있는 항목을 확인합니다. 키 값은 화면, 로그, 커밋, 이슈, 완료보고서에 출력하지 않습니다.
2. DART 인증키는 서버 secret으로 설정합니다. `VITE_` 변수에는 넣지 않습니다. 미발급이면 사용자가 할 가입/신청/승인 절차를 정확한 공식 링크와 설정 위치로 한 번에 정리합니다. 나머지 독립 구현과 테스트는 계속합니다.
3. 시세 공급자는 최신 공식 문서와 웹사이트 표시/재배포 권한을 확인하여 선택합니다. 개인 증권계좌 API를 불특정 사용자 사이트에 그대로 표시해도 된다고 추정하지 않습니다. 임의 스크래핑·출처 불명 시세·mock으로 대체하지 않습니다.
4. Node 22 백엔드, HTTPS, 영속 저장소, 운영 로그/health를 갖춘 환경을 준비합니다. 사용 가능한 기존 환경을 우선하며, 새 유료 계약·결제·법적 동의는 사용자에게 구체적인 비용/조건 확인이 필요한 항목입니다. 확인 전에도 코드·컨테이너·배포 설정은 준비합니다.
5. 단일 수집 프로세스로 먼저 안정화합니다. 다중 인스턴스를 쓰면 공용 요청 제한, 임대 갱신/작업 중복 방지와 실제 PostgreSQL 통합 검증까지 수행합니다.

### B. 기존 어댑터의 정확성 보완

기존 구현을 완성품으로 가정하지 말고 아래 항목을 직접 점검하세요.

- SEC는 키 없이 접근 가능하지만 이전 환경에서는 HTTP 403이었습니다. 적절한 운영 연락처 User-Agent와 공식 요청 제한을 적용하고 실제 호스팅에서 검증하세요. 차단을 우회하지 않습니다.
- SEC ticker → CIK, DART 종목코드 → corp_code를 검증된 공식 목록으로 매핑합니다. 현재 DART 회사코드는 삼성전자부터만 등록되어 있습니다. 국내 관심 종목 여러 개를 지원할 수 있게 확장하세요. GOOG/GOOGL 등 복수 증권의 같은 발행회사 수집은 합칩니다.
- SEC US-GAAP / IFRS / 회사 고유 태그를 구분합니다. 지원하지 않는 항목은 이유를 표시합니다. 일반 회사와 은행·보험·REIT의 분석 정책을 분리합니다.
- 연결/별도, 통화, 결산기, 52/53주 회계연도, 단일 분기/누적/연간/TTM을 혼합하지 않습니다. 잔액은 합산하지 않습니다. TTM은 연속 4개 분기 흐름의 합계입니다.
- SEC 누적 차감 시 정정 전후 accession의 혼합, 서로 다른 분모/기간이 섞인 값, 최신 XBRL 미도착을 다룹니다. DART `thstrm_amount`/`thstrm_add_amount`와 Q4 연간−9개월 변환을 원문으로 대사합니다. 코드에 있는 12월 결산 전제를 지원 범위에 맞게 제거하거나 명시합니다.
- 부채비율은 부채총계/자본총계. ROE는 동일 귀속 순이익/기초·기말 평균자본. 재고 회전율은 매출원가/평균재고. 매출채권 회전율은 신용매출이 없으면 총매출 근사라고 표시합니다.
- 영업현금흐름과 순이익의 연결 전체/지배기업 귀속 차이를 확인합니다. 음수·0 분모, 자본잠식, 누락 값을 일반 정상 지표처럼 계산하지 않습니다.
- FCF는 정의와 현금 CAPEX 범위를 고정하고, 유형/무형 취득액·양수/음수 표시 관행을 검증합니다. 미공시를 무조건 0으로 처리하거나 투자현금흐름 전체를 CAPEX로 대체하지 않습니다.
- PER/PBR의 보통주 귀속 이익·자본과 주식 종류, 회사 전체 시가총액의 범위를 맞춥니다. ADR/분할/자사주/희석/복수 주식 종류를 고려합니다. 다른 통화를 환율 출처·시각 없이 섞지 않습니다.
- 현재 일부 보통주 계정은 데이터가 없어 계산 보류됩니다. 단순히 총자본을 보통주 자본으로 이름만 바꿔 숫자를 채우지 마세요.
- `자산=부채+자본` 대사, 큰 변동/중복 기간/미래 공시일/잘못된 통화 등을 검사하고 실패 상태를 표시합니다.
- 시가총액·시세 응답은 서버와 프런트 모두 런타임 검증합니다. 공급자 이름, quoteAt, realtime/delayed/close, 통화와 지연 시간을 유지합니다. API 조회시각을 거래 체결시각으로 사용하지 않습니다.
- 투자 해석은 증거와 불확실성을 표시합니다. Altman 점수를 보편적인 부도 확률로 취급하지 않습니다. TAM/WACC/차입 만기/고객 집중/일회성 손익은 근거가 없으면 미확보로 둡니다. 이번 목표는 실데이터 연결이며 AI 문구 생성으로 검증을 대신하지 않습니다.

### C. 실제 시세 어댑터 구현

`QUOTE_SERVICE_URL`에 임의 예시 URL을 넣는 것으로 끝내지 마세요. 선택한 실제 공급자와 연결하는 어댑터를 구현하고 인증/심볼/요청 제한/오류/시장 시간 정책을 테스트하세요.

기존 화면과 맞출 기본 응답: `price`, `marketCap`(확보 가능할 때), `currency`, `quoteAt`, `delayClass`, `source`. 필요한 `fetchedAt`, `delayMinutes`, 시장 상태, 조정 여부 등을 추가해도 됩니다. provider 원본 응답을 무검증 통과시키거나 비밀 필드를 그대로 반환하지 않습니다.

국내/미국의 실시간 제공 범위가 다르면 각각 표시합니다. 장이 닫혔으면 마지막 거래/종가 시각을 보여줍니다. 휴장 중 숫자가 안 바뀌는 것을 오류로 판단하거나 현재 시각으로 덮어쓰지 않습니다.

### D. 운영 수집·배포 연결

- 보관본을 즉시 제공하고, 5분 TTL은 공시 확인 주기임을 유지합니다. 정정 공시/새 버전을 보존하며 실패 때 마지막 성공본·성공 시각을 덮어쓰지 않습니다.
- 요청 중복 제거, 429/5xx/시간 초과 backoff, 재시작 복구, 임대 만료/소진 작업, 신규 공시의 XBRL 지연을 검증합니다.
- 현재 단일 JSONB 상태 레코드는 초기용입니다. 실제 사용 규모에 맞는 저장 구조·백업·용량 상한·원문 보존 정책을 구현합니다. 원문 스냅숏에는 provider, URL/식별자, 수집시각, 해시, 정정 연결을 남깁니다. 키가 포함된 원문 요청 URL은 반드시 제거합니다.
- CORS는 실제 Pages origin 허용. HTTPS·타임아웃·요청량 제한·운영 health를 점검합니다. `/health` 응답에 비밀값이 없어야 합니다.
- 백엔드 staging을 배포하고 프런트엔드 staging에서 실제 종목 조회를 먼저 검증합니다. Pages Actions 변수 `VITE_FINANCIAL_API_URL`은 공개 HTTPS 주소입니다. 서버 secret을 프런트 빌드에 넣지 않습니다.
- 기존 사이트 배포까지 사용자 승인된 범위입니다. 테스트와 대사가 통과하면 main/Pages 및 운영 백엔드에 반영할 수 있습니다. 기존 배포 URL과 사용자 로컬 데이터를 보존하고, 롤백 가능한 커밋·설정을 기록합니다.

## 3. 반드시 실행할 검증

기준 테스트는 직전 릴리스 172개이며, 시작 시 최신 main의 수치를 사용하세요. 수를 맞추려고 테스트를 삭제/완화하지 않습니다.

```sh
npm ci
npm test
npm run typecheck:packages
npm run typecheck:server
npm run build
```

수정한 파일 ESLint도 확인합니다. 전체 lint에 기존 오류가 있다면 시작/종료 차이를 분리해서 기록합니다.

추가 테스트:

1. 원문 대사: 국내 삼성전자 + 비금융 국내 다른 기업 1개 이상, 미국 NVDA/MSFT 포함 2개 이상. 각 기업 최근 연간 및 분기 공시에서 매출·영업이익·순이익·자산·부채·자본·OCF·CAPEX와 주요 비율을 대사합니다. 누락은 이유를 기록합니다.
2. 경계 표본: 금융업 1개, 적자/자본잠식 1개, 정정 공시 1개, 비12월 결산 또는 53주 회계연도 1개. 한 기업이 여러 조건을 충족해도 됩니다. 지원 제외가 정답인 경우에는 명확한 보류와 근거를 검증합니다.
3. 통화·귀속·기간이 다른 숫자로 계산하지 않는 테스트. TTM, 평균 잔액, 정정 누적 차감, CAPEX 부호에 대한 독립 기대값.
4. 실제 시세: 국내/미국 각각 가격·거래시각·지연 구분·통화·식별자 대사. 시가총액과 재무 귀속의 불일치 때 PER/PBR 보류 확인.
5. 운영: 동시 사용자 요청, 제공자 429/500/timeout, DART 키 누락/무효, 최신 XBRL 대기, 중복 작업/임대 만료, 프로세스 재시작, 실제 PostgreSQL을 선택했다면 실제 DB 테스트.
6. 브라우저: 관심 등록→조회→새로고침→보관본→갱신 실패→다시 성공. 데스크톱과 스마트폰 폭에서 확인하고 가능하면 실제 Safari/Android 설치 앱에서도 확인합니다. 화면 크기 에뮬레이션을 실제 휴대폰 검증이라고 쓰지 않습니다.
7. 기존 Stock 종목·뉴스·관심 목록·`/#/lab` 실행/취소/저장/공유 회귀. 모바일 업데이트 안내와 계산 중 업데이트 차단도 확인합니다.
8. 키가 Git history, dist JS, 브라우저 네트워크, 서버/Actions 로그에 노출되지 않았는지 확인하되 검사 출력에 키를 남기지 않습니다.

## 4. Codex에 넘길 완료 패키지

`docs/hermes-financial-live-report.md`를 작성하고, 대사표·재현 스크립트·비밀값 없는 응답/로그·화면 증거는 `docs/evidence/financial-live/`에 보관하세요. 라이선스가 원본 재배포를 금지하면 원문 전체를 커밋하지 말고 접근 절차/식별자/해시와 허용된 검증 결과만 남깁니다.

보고서 필수 항목:

- 상태: `READY_FOR_CODEX_REVIEW` 또는 `BLOCKED_EXTERNAL_SETUP`. 스스로 `CODEX_VERIFIED`라고 쓰지 않습니다.
- 시작 SHA, 최종 SHA, 브랜치, PR, 변경 파일과 핵심 결정
- 실제 백엔드/프런트 배포 URL, Actions run URL, 배포 시각, 현재 운영 버전
- 공급자·시장별 제공 범위, 지연 조건, 확인한 공식 문서 링크
- 환경변수 **이름과 설정 위치만**, 필요한 사용자 작업/외부 승인 목록
- 종목별 원문 대사표: ticker/issuer, period/scope/currency, account, source value, normalized value, formula/result, tolerance, filing ID/URL, 확인시각
- 테스트 명령·통과/실패 수·실행 로그 위치, 수동 검증 결과와 실제 기기/에뮬레이션 구분
- 보관본/정정/재시작/실패 처리 증거, 개인정보·비밀값을 제외한 운영 로그
- 알려진 미완료, 지원하지 않는 시장·업종·지표, 롤백 절차와 백업 확인

외부 준비 때문에 실제 데이터나 배포를 검증할 수 없으면 그 부분을 완료로 쓰지 마세요. 이미 가능한 구현·staging·테스트·운영 문서를 마친 뒤, 사용자가 해야 할 정확한 마지막 단계를 제시합니다.

## 5. Codex 독립 검증과 보완 반복

헤르메스 구현·대사·테스트 → 위 보고서와 SHA/PR/URL 전달 → **현재 사용자와 작업 중인 Codex가 독립 검증** → 문제 목록 전달 → 헤르메스 수정 → Codex 재검증 순서입니다.

Codex는 보고서만 믿지 않고 다음을 다시 확인합니다.

- 인계한 정확한 SHA에서 변경 코드와 데이터 정책 리뷰, 자동 테스트/빌드 재실행
- 대표 국내/미국 기업의 공시 원문·시세 시각과 지표를 독립 표본 대사
- 운영 API와 공개 화면의 버전·보관본·실패 상태·비밀값 경계 확인
- 모바일 갱신 및 시뮬레이션/기존 Stock 회귀 확인
- 결과를 `PASS`, `CHANGES_REQUIRED`, `BLOCKED_EXTERNAL_SETUP`으로 구분하고, 잔여 위험·지원 범위를 보고

`CHANGES_REQUIRED`이면 헤르메스가 수정 커밋과 재검증 증거를 제출하고 Codex가 다시 확인합니다. PASS가 나기 전에는 사용자에게 최종 검증 완료라고 보고하지 않습니다.

실제 에이전트 간 반환 채널이 있으면 위 패키지를 그 채널로 전달하세요. 채널이 없으면 최종 응답에 아래 인계문을 출력하여 사용자가 현재 Codex 대화에 전달할 수 있게 합니다. 자동으로 Codex가 깨어나거나 검증이 실행된다고 주장하지 않습니다.

> Codex 검증 요청: Stock 실제 재무·시세 연결 구현을 마쳤습니다. SHA: … / PR: … / 프런트 URL: … / API URL: … / 보고서: … / 미완료: … . `docs/hermes-financial-live-handoff.md`의 독립 검증 기준에 따라 검증하고, 보완이 필요하면 헤르메스에게 수정 목록을 전달해 주세요.
