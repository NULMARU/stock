# 시뮬레이션 모델 정밀도와 검증 설계

작성일: 2026-09-12 · [개발계획](simulation-lab-development-plan.md)의 계산 모델 명세

아래는 구현할 모델의 계약과 검증 기준이다. 제안 수식과 수치는 새 모델이 이미 현실을 잘 예측한다는 주장이 아니다. 원본의 실제 동작, 개선할 구조, 데이터로 검증해야 하는 가정을 구분한다.

## 2. 모델 정체성과 버전 정책

`legacy-09c710e`는 원본 결과의 재현에 사용한다. Structural v2는 새 수학 모델이며 기존 결과와 수치 일치를 목표로 삼지 않는다. 단위와 자원 제약을 수정하면 병목·매출·투자 경로가 크게 달라질 수 있다. 원본 154개 테스트는 legacy 계약에 남기고 v2에는 독립 계산 예제와 구조 검증을 추가한다.

버전은 각각 `engineVersion`(실행·수치 알고리즘), `modelVersion`(수식·구조), `calibrationVersion`(계수), `datasetVersion`(관측 스냅샷), `adapterVersion`(14입력 변환), `schemaVersion`(저장 형식)으로 분리한다. 단순 화면 변경은 모델 버전을 올리지 않는다. 저장 형식 마이그레이션과 모델 가정 변경은 다른 작업으로 취급한다.

구버전 실행 파일은 입력·결과·버전을 포함하므로 재실행 엔진을 지원하지 않더라도 결과를 읽을 수 있다. 구버전 모델에서 새 모델로 이동할 때는 새 시나리오 사본, 변환 가능한 입력, 버려지는 가정, 새 기본값 목록을 만든다. ‘같은 시나리오’라는 이유로 기존 결과를 덮어쓰지 않는다.

## 3. 단위·재고·흐름 계약

| 양 | 정규 단위 | 종류·정의 |
|---|---|---|
| 설치 전력 | MW | 특정 시점 사용 가능한 설비 용량. GW는 입력 경계에서 ×1,000 |
| 전력 효율 | PFLOPS/MW | 같은 연산 정밀도·작업 부하 기준의 변환 계수 |
| 연산 용량 | PFLOPS, 별도 작업량/기간 | FP16/FP8/INT8 등 기준을 metadata에 명시, 숫자만 합하지 않음 |
| 메모리 | GB 설치량, GB/s 대역폭, GB/분기 신규 공급 | 용량·대역폭·신규 공급을 다른 변수로 관리 |
| 패키징 | wafer/분기 및 accelerator/분기 | wafer당 칩 수·수율·칩별 메모리 요구량으로 변환 |
| 금액 | USD billion, priceBaseYear 명시 | 매출·운영비·투자와 자산/잔액 분리. 실질/명목 혼합 금지 |
| Physical 기기 | units | 설치 수량, 활성 수량, 신규 배치 수량 분리 |
| 수익률·효율 비율 | 0–1 | UI 퍼센트는 입출력 경계에서 변환 |
| 시간 | 정수 분기 인덱스 + 기준 분기 | 금액 흐름은 해당 분기 합계, 용량은 시작/종료 상태 구분 |

TypeScript 브랜드 타입은 잘못된 조합을 줄이지만 JSON의 런타임 검증을 대신하지 않는다. `min()`은 같은 종류·단위로 환산된 양끼리만 허용한다. 매출처럼 분기 흐름은 합산할 수 있고 설치 용량은 연말값/평균값을 선택해야 하므로 `MetricDefinition.aggregation`을 필수로 둔다.

단위 sanity fixture는 소스 구현과 별도로 계산한다. 예를 들어 `45 GW × 1,000 MW/GW × 20 PFLOPS/MW = 900,000 PFLOPS`, `70,000 units × ($100,000/unit × 0.9/year) ÷ 4 ÷ 10^9 = $1.575B/quarter`이다. 후자는 수익률 가정의 현실성을 증명하는 예제가 아니라 환산 검증이다.

## 4. Structural v2 계산 구조

**수요·설치 용량·실제 처리량·재투자 자금을 별도 상태로 둔다.** 최초 구현은 해석 가능한 분기 차분 모델이며 단위만 고친 원본 수식을 그대로 연장하지 않는다.

분기 t의 순서:

1. 기초 재고와 예정된 설비 준공을 반영한다. 준공은 거래 ID별로 한 번만 처리한다.
2. 외생 기술 추세와 해당 분기 사건의 운영 충격을 적용한다. 설비 파괴, 가동 중단, 신규 투자 지연을 구분한다.
3. 생산·메모리·전력·네트워크 제약을 같은 작업량 단위로 변환한다.
4. 훈련, 클라우드 추론, 엣지 추론에 공급 예산을 배분한다. 배분량 합계가 가용량을 넘지 못한다.
5. 수요와 처리 가능한 작업량으로 실제 제공량을 결정하고 매출·비용·가용 현금을 계산한다.
6. 재투자 비율·외부 정책 자금으로 신규 투자를 기록한다. 다음 시점의 준공·재고 상태를 산출한다.

핵심 식의 형태:

```text
capacityNext = max(0, capacityStart + commissionedCapacity - retirement - destruction)
allocatedTraining + allocatedCloudInference + allocatedEdgeInference <= availableCompute
servedDigital = min(digitalDemand, digitalServingCapacity)
servedPhysicalTasks = min(physicalTaskDemand, edgeServingCapacity)
activeFleet <= min(deployedFleet, taskSupportedFleet)
revenue = servedQuantity * unitPrice
availableCash = revenue - explicitOperatingCosts - otherModelledOutflows
newInvestment <= max(0, availableCash) * reinvestmentRatio + externalFunding
```

Physical AI 활성화는 능력·지연 임계값을 통과하고 **실제 공급 용량이 있을 때** 성립한다. 클라우드와 엣지의 용량을 양쪽에서 전부 사용하는 이중 계상을 막는다. 작업당 추론량, 기기당 작업 수, 패키징 수율 등의 환산 계수가 없으면 임의의 사실값을 넣지 않고 ‘가정’으로 명시한다.

원본의 매출×매출총이익률은 실제 현금흐름과 같지 않다. 초기 v2에서 OPEX 등을 단순화하면 항목별 가정을 노출하고 결과를 ‘모델상 재투자 가능 금액’으로 부른다. Digital/Physical 매출의 시장 범위를 문서화하여 같은 서비스를 두 번 합산하지 않는다.

병목은 변수/임의 최대값의 최솟값에서 **수요 대비 공급 충족률 및 제약 이유 목록**으로 바꾼다. 훈련·클라우드·엣지 각각의 병목을 계산하고 6노드 화면은 이를 요약한다. 단일 최저 노드만 강조해 아직 작동하지 않는 엣지 부문이 전체 산업을 항상 결정하는 문제를 피한다.

## 5. 시간과 투자 지연

`ProjectCommitment`는 id, commitmentQuarter, amount, targetSubsystem, expectedCommissionQuarter, commissionedAmount, status를 가진다. t에 투자하고 lead=4분기이면 t+4 **분기 시작**에 사용 가능하다는 계약으로 정한다. 0지연 투자는 다음 분기 시작으로 제한하거나 명시적으로 허용하되 첫 모델에서는 최소 1분기로 고정한다.

리드타임 충격은 새 투자에 적용하고 진행 중 프로젝트는 별도의 지연 사건이 해당 프로젝트의 준공일을 한 번 변경한다. 매 분기 현재 lag로 과거 투자 배열을 다시 선택하지 않는다. 집행·취소·미집행 잔액의 합이 약정 투자액과 일치해야 한다. 미래 사건을 추가해도 사건 전의 모든 결과는 그대로여야 한다.

유기적 기술 변화와 투자에 의한 증가를 별도 함수로 분리한다. 투자 0일 때 어느 기술 추세가 유지되고 어느 증가가 0인지 metadata로 규정한다. 디폴트 성장률·최대값은 엔진 소스의 숨은 상수가 아니라 버전이 있는 가정 세트에 둔다.

월별 확장은 이후에 `r_month=(1+r_annual)^(1/12)-1`, 월별 흐름·준공 시간·사건 지속 기간·계절성을 함께 정의한다. 분기 금액을 단순히 세 번 계산하지 않는다. 같은 모델을 두 시간 간격으로 푸는 경우 수렴을 검증하고, 다른 월별 모델이면 별도 모델 버전으로 비교한다. 시간 step만 늘려 2035년 정확도가 높아졌다고 표현하지 않는다.

## 6. 관측 데이터와 보정 계획

1차 보정 범위는 **정의가 비교 가능한 데이터가 있는 지표부터**다. 출처 후보는 기업 공시의 CAPEX·사업부 매출, 공식 전력·설비 통계, 제조사 공개 기술 사양 및 생산 자료다. 이 문서 작성 중 해당 데이터의 확보·사용권·비교 가능성은 확인하지 않았으며 수집 완료를 전제하지 않는다.

모든 관측값에 관측 기간, 발표일, 수집일, 출처 URL, 개정판, 통화·가격 기준, 지역·시장 범위를 저장한다. 과거 시점 평가에는 그 시점에 발표된 값만 사용한다. 현재 `Base Case 2026` 가정을 2025Q1부터 적용한 결과는 과거 예측 검증에 사용할 수 없다.

최초 보정 범위 결정 절차:

- 지표별로 최소 16개 분기 이력 확보를 목표로 하되, 확보된 범위와 결측을 먼저 보고한다. 충분하지 않으면 해당 지표는 가정 기반 상태로 유지한다.
- 직접 관측 가능한 계수를 고정하고 민감한 소수의 미관측 계수만 보정한다. 수십 개 계수를 소수 매출 시계열에 한꺼번에 맞추지 않는다.
- 같은 수치가 글로벌·한국·특정 기업 중 무엇을 뜻하는지 고정한다. 글로벌 클라우드와 한국 엣지를 함께 쓰는 경우 다중 지역 시나리오라고 선언하며 근거 없는 전체 합계를 만들지 않는다.
- 예측 시점 기준 학습/보정 구간과 평가 구간을 분리하고 마지막 4개 분기를 초기 holdout 후보로 둔다. 가능한 기간에는 rolling-origin 방식으로 1분기·4분기 앞을 평가한다. 표본이 부족하면 탐색 결과로만 보고한다.
- 최소 기준선은 마지막 관측값 유지, 단순 성장률 외삽이다. 양수 지표는 WAPE, 전체 지표는 MAE와 스케일을 함께 보고한다. 분모가 0에 가까우면 상대 오차를 억지로 계산하지 않는다.

초기 채택 규칙은 평가 전에 고정한다. 예를 들어 주요 지표의 holdout WAPE가 강한 기준선 대비 10% 이상 개선되고 물리 검증·지역별 오차를 악화시키지 않는 것을 목표로 삼을 수 있다. 10%는 계획상의 후보 임계값이며 측정 결과가 아니다. 표본과 지표를 확정한 후 튜닝 전에 규칙을 문서화하고, 평가 데이터를 보고 임계값을 낮추지 않는다. 기준선을 못 이기는 지표는 구조 탐색용으로 유지한다.

AI 전체 매출·CAPEX처럼 기업 간 정의가 다른 값을 단순 합산해 정답 데이터로 취급하지 않는다. 원시 자료를 재배포할 수 없는 경우에는 허용된 파생 값과 추출 근거, 해시만 배포하는 경로를 선택한다.

## 7. 민감도와 불확실성

처음에는 각 입력의 합리적 범위 내 상·하 변화와 2변수 격자를 이용한다. 원본처럼 임계값·상한·포화가 있는 모델에서는 최종 분기만 보면 효과를 놓치므로 매출 누적, 제약 발생 분기, 활성화 시점도 관찰한다. 영향이 큰 입력과 서로 대체 가능한 입력을 식별한 뒤 보정 우선순위를 정한다.

다음 단계에서 seed가 있는 샘플링을 추가한다. 관측값의 오차, 알려지지 않은 계수, 사건의 조건부 시나리오를 각각 분리한다. 근거 없는 균등/정규분포를 기본적인 사실로 제공하지 않는다. 분포를 지정하지 않은 경우에는 결정론적 범위 탐색으로 실행한다.

상관 행렬은 대칭·대각 1·유효성을 검증하고 샘플링 순서와 PRNG 버전을 고정한다. 사건 발생을 사용자가 전제로 선택한 경우, 그 결과 밴드는 사건 자체의 발생 확률을 포함하지 않는다. 구조 모델이 빠뜨린 변수의 위험도 Monte Carlo 밴드가 자동으로 포함하지 않는다.

출력은 P10/P50/P90과 표본 수, 가정 분포, 사용한 상관, seed, 샘플링 안정성을 포함한다. 250→500→1,000개 등 샘플 수를 늘려 주요 분위수 변화를 비교한다. 확률 구간의 실제 포함률은 별도의 미사용 관측값과 표본 수·구간 불확실성을 함께 평가한다. 예측 origin이 겹치는 관측을 독립 표본으로 세어 근거를 과장하지 않는다.

물리 불변조건은 v2의 필수 통과 항목이며 1개 실패해도 정상 실행 결과로 게시하지 않는다. 순간 공급 증가가 장기 전체 매출을 항상 올려야 한다는 식의 무조건 단조성 검사는 사용하지 않는다. 수요 상한, 비용, 재투자, 다른 병목 때문에 전 구간 단조성이 성립하지 않을 수 있다.

수치 비교는 처음부터 반올림해서 오류를 숨기지 않는다. 동일 런타임 반복은 계산 순서가 동일한 경우 정확 일치를 검사한다. 플랫폼 간 기본 비교는 `abs(a-b) <= atol + rtol*max(abs(a),abs(b))`, 초기 `rtol=1e-9`를 사용하고 atol은 단위별로 규정한다. 임계 활성화 분기는 별도로 일치시켜 경계 근처 오차를 숨기지 않는다. 실제 데이터 오차 기준에 이 수치 허용오차를 대신 사용하지 않는다.

릴리스 모델 카드에는 목적·범위, 기준시점, 수식·단위, 데이터 계보, 보정/평가 분리, 지표별 오차, 민감도, 알려진 실패 영역, 변경 이력을 기록한다. 현재 확인되지 않은 예측 정확도는 목표와 미검증 상태로 남긴다.

## 10. 재무제표와 기업 모델 확장 — 2026-09-13

관심 종목 재무 기능은 [재무제표 계획](financial-statements-feature-plan.md)의 FS01–FS12 계산 계약을 따른다. 재무 기능 작업은 백로그의 FR01–FR14로 추적한다.

기업 모델 `corporate-finance-v1`은 개별 회사의 보고 통화·연결 범위·공시 시점이 고정된 스냅샷을 입력으로 받는다. 기존 산업 InfraWheel의 글로벌 매출·전력·CAPEX 계수로 회사의 현금흐름을 계산하지 않는다. 기업 모델 추가 시 다음 검증을 기존 V01–V13에 더한다.

- 누적·단일 분기·TTM 변환과 평균 잔액 검증, 연결·귀속·통화의 일치.
- 기간별 현금 원장: 기초현금 + 영업/투자/재무 흐름 + 필요한 환산 등 조정 = 기말현금.
- CAPEX·배당·리스·이자·부채상환이 현금흐름과 여력 계산에 두 번 반영되지 않음.
- 금리 충격은 계약상 영향을 받는 차입에만 적용하고 운전자본 회수 지연은 해당 매출·기간·현금 흐름과 일치.
- 보고치·계산치·AI 해석·사용자 가정의 provenance를 분리. 회사·기간·수치·근거 불일치 차단.
- Altman 점수, OCF/순이익, ROIC−WACC의 적용 조건·정의·결측 상태를 검증. 모형 점수를 부도 확률로 직접 전환하지 않음.
- 사용자 가정에 따른 현금 부족 결과와 실제 부도 판정·주가 예측을 구분. 자료 부족한 만기·제한현금·한도는 0으로 간주하지 않음.

기업 재무의 수계산 fixture와 회계 대사를 통과해도 예측의 현실 정확도가 검증되는 것은 아니다. 향후 기업 모델을 보정할 때도 당시 공개된 공시만 사용하고 기업별 holdout과 단순 현금흐름 기준선으로 비교한다.
