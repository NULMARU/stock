## 독립 수계산 사례

아래는 실제 회사 자료가 아닌 계산 검증 전용 입력이다. 구현의 수식을 그대로 복제하지 않고 기대 결과를 먼저 고정한다.

- 매출 1,000, 매출원가 600, 영업이익 200, 순이익 100, 평균자산 1,000, 평균자본 500이면 영업이익률 20%, ROE 20%, 듀폰 분해는 10% × 1 × 2 = 20%다.
- 기말부채 600, 기말자본 400이면 부채비율 150%다. 기말자본 0 또는 음수일 때 일반적인 건전성 비율로 해석해서는 안 된다.
- 영업현금 150, 현금 CAPEX 40, 기업 인수 30이면 정의한 FCF는 110이다. 인수액을 CAPEX에 섞어 FCF를 80으로 만들지 않는다.
- 평균재고 100이면 재고회전율은 원가 기준 6회, DIO는 연간 365일 기준 약 60.833일이다. 매출 기준 10회는 이 계약의 재고회전율이 아니다.
- 매출채권 평균 125, 신용매출 1,000이면 회전율 8회, DSO 45.625일이다. 신용매출이 없고 총매출을 쓰면 대체값 사용을 표시한다.
- 현금 100, 기초 분기 이후 OCF 30, CAPEX 10, 배당 5, 순차입 -8, 기타 현금 조정 2이면 기말현금 109다. 이자 등이 이미 OCF에 반영되었을 경우 재차 차감하지 않는다.
- Q1 누적매출 100, H1 250, 9개월 450, 연간 700이면 단일 분기는 100/150/200/250, TTM은 700이다. 재무상태표 잔액은 이 방식으로 차감·합산하지 않는다.
- 보고 범위·통화·개정 기준이 다른 분기의 합계는 TTM으로 게시하지 않는다. 결측은 0으로 대체하지 않는다.

### 재개 시 우선 수정할 검토 항목

1. `runner.ts`: 버전 검사 반복문의 무조건 `break` 제거, 실행 모델 ID·model/engine/calibration/adapter 버전 일치 검증. 정규화된 입력을 실제 실행·해시에 사용하고 원본 입력과 결과를 별도 복제·불변 처리. 실행 기록에 상세 원장을 보존하고 저장 결과와 결과 해시의 구성 요소를 일치시킨다.
2. `sampling.ts`: `[[1,1,0],[1,1,1],[0,1,1]]`은 음의 고유값이 있는데도 통과한다. Cholesky 영 피벗의 비영 잔차를 거부하고 유한한 행렬, 중복 변수, 분포 종류·경계, 샘플 번호를 검증한다. `{kind:'invalid'}`도 통과하는 누락된 switch 기본 분기를 수정한다. 유효 특이행렬과 무효 특이행렬을 각각 시험한다. 분위수는 NaN/Infinity를 거부한다.
3. 수동 UTF-8 encoder로 바꾼 뒤 한글은 표준과 일치하지만 단독 surrogate `\ud800`/`\udc00`의 SHA-256은 Node 표준 UTF-8과 불일치한다. 해당 입력 정책을 정하고 표준 대체문자 처리 또는 명시적인 거부를 적용한다.
4. v2 기본 가정: 350 TOPS는 0.35 POPS이며 0.00035가 아니다. FP16 연산량과 비교하려면 별도 정밀도·작업량 변환이 필요하다. `1.5e-6 $B`는 $1,500이지 주석의 $1.5M가 아니다. `70,000 × 20,000 × $0.0001575 / 10^9 = $0.0002205B`로 주석의 $1.575B와 다르다. 가정은 가정으로 명시하고 값·단위·예제·주석을 일치시킨다.
5. v2 메모리 용량·대역폭·패키징 공급 흐름을 구분하는 승인 계획을 단일 계수로 축소하지 않는다. 전력·연산·투자·현금 원장 제약과 함께 모델을 완성하고 G1을 검증한 뒤 UI에 연결한다.
6. 모든 설계 문서의 나머지 백로그는 계속 미구현으로 취급한다. 인증키가 없다는 사유로 계산·연동 코드까지 완료된 것으로 표기하지 않는다. 실제 관측 데이터가 없는 경험적 보정·정확도는 미검증으로 남긴다.

세부 검토 의견은 기존 Dispatch 수신함에도 전달했으나, Kimi는 한도 오류 전에 이를 반영 완료하지 못했다. 새 구현 담당은 이 인계 문서와 기존 계획을 함께 읽고, 기본 테스트 통과를 수정 항목 통과로 오해하지 않아야 한다.
