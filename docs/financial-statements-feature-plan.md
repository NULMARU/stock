# 관심 종목 재무제표·쉬운 해석 기능 계획

작성일: 2026-09-13 · 상태: 요구사항과 개발계획 반영 완료, 구현 전

최신 조회 요구 반영: [실시간 시세·최신 공시 조회 설계](financial-live-data-plan.md)의 서버 API와 요청 시 수집을 첫 릴리스에 포함한다.

**목표: 관심 종목의 재무제표를 보고 ‘이 회사가 돈을 잘 벌고, 현금을 확보하며, 성장을 지속할 수 있는지’를 쉽게 이해하게 한다.** 재무상태표·손익계산서·현금흐름표, 계산한 지표, 공시에 근거한 해석, 사용자가 바꿔 보는 가정을 연결한다.

[전체 개발계획](simulation-lab-development-plan.md)에 추가하는 Stock 본체 기능이다. 시뮬레이션 랩은 계속 독립된 내부 앱으로 개발하며, 재무제표 조회는 랩 완성을 기다리지 않고 먼저 출시할 수 있다. 아래 12개 항목은 사용자가 제공한 자료의 핵심을 반영한 제품 요구사항이다. 문장 중 끼어 있는 페이지 번호 등은 지표로 취급하지 않았다.

## 1. 화면과 관심 종목

진입 경로는 `관심 종목 카드 → 재무 보기 → 재무 요약 / 재무제표 / 심화 해석`이다. 정식 학습 종목 외에 사용자가 검색·추가한 종목도 같은 경로를 제공한다. 재무 경로 `#/stock/:ticker/financials`는 기존 `StockDetailPage`의 26개 종목 검색 성공에 의존하지 않고 발행회사 식별자로 조회한다.

| 화면 | 보여줄 내용 |
|---|---|
| 관심 종목 카드 | 최신 공시 기간, ‘영업현금흐름 개선’ 같은 확인된 변화 1개, 재무 보기. 신호가 없으면 만들지 않음 |
| 재무 요약 | 최근 중요 변화 3개와 6개 영역 카드. ‘괜찮은 점 / 살펴볼 점 / 아직 모르는 점’ |
| 재무제표 | 손익·재무상태·현금흐름 주요계정 표, 제공되는 자본변동 항목, 연간/분기/TTM 선택, 원문 전체 제표 링크 |
| 항목 상세 | 실제 수치 → 기간별 추세 → 왜 중요한가 → 가능한 원인 → 공시 근거 → 다음 확인 질문 |
| 심화 해석 | 만기·일회성 손익·고객 집중·자본배분·회계 주석을 근거로 설명. 원문 문단/표로 이동 |
| 비교 | 같은 업종·회계 범위·기간의 최대 3개 관심 종목. 금융업과 일반기업 등 비교 불가 항목은 분리 |
| 조건 바꿔 보기 | 지원하는 기업 현금흐름 시나리오를 랩에서 열고 금리·회수일·마진 등의 가정을 변경 |

기본 조회 이력 목표는 연간 5년, 분기 8개다. 실제 확보한 기간만 표시하고 8분기 미만이라고 추정치를 채우지 않는다. TTM은 ‘최근 12개월’로 풀어 쓰며 연간/분기/TTM을 한 차트에서 동일 기간처럼 이어 붙이지 않는다.

현재 `addedStocks`는 간이 종목 목록이고 `newsChecked`는 뉴스 구독이다. `watchedSecurities`를 별도로 두고 명시적으로 관심 등록한 기존 `addedStocks`를 이전한다. 기본 학습 종목 26개와 뉴스 구독 목록 전체를 자동 관심 등록하지 않는다. 기존 간이 카드의 ‘다음 자동 갱신부터 재무 분석 반영’ 안내는 실제 수집 보장과 맞지 않으므로 지원 상태에 맞는 문구로 바꾼다.

사용자가 관심 종목의 재무 화면을 열면 서버 API가 검증된 자료를 먼저 반환하고 새 공시를 확인한다. 지원하는 발행회사에 기존 자료가 없으면 수집 작업을 예약해 진행 상태를 표시한다. 미지원·미식별 종목은 이유와 확인 가능한 공시 경로를 제공한다. 관심 목록 전체를 서버로 전송할 필요는 없으며 요청한 회사만 조회한다. 상세 API·최신성 계약은 [최신 조회 설계](financial-live-data-plan.md)를 따른다.

## 2. 12개 항목의 계산과 해석 계약

금액·기간·연결 범위를 맞춘 계산은 결정론적 코드가 담당한다. AI는 계산값과 공시 근거로 해석을 작성한다. A는 원문 재무 수치로 계산, B는 주석·사업보고서가 있어야 해석, C는 외부 데이터·추정 가정이 필요한 항목이다.

| ID·영역 | 사용자가 보는 질문 | A: 기본 지표·계산 | B/C: 추가로 제공할 해석과 필요한 근거 |
|---|---|---|---|
| FS01 안정성 | 빚과 이자를 감당할 수 있나요? | 부채총계/자본총계, 이자보상배율(EBIT/이자비용), 현금·이자부차입금 | B: 차입 만기·담보·약정·계속기업 관련 주석, 설비투자·차입·자사주 거래 맥락. C: 적용 가능한 Altman 모형의 재무곤란 신호와 금리·차환 스트레스 |
| FS02 안정성 | 가까운 시일에 돈이 부족해질 수 있나요? | 유동자산/유동부채, 현금성자산, CCC=DSO+DIO−DPO | B: 사용제한 현금, 향후 12개월 상환, 미사용 신용한도·사용 조건. C: 매출 회수 지연·차환 실패 가정에 따른 지급 여력 |
| FS03 수익성 | 이익을 꾸준히 벌고 있나요? | 영업이익/매출, 보고 이익과 OCF 추세 | B: 일회성 손익·주식보상·손상·구조조정과 반복 가능성. 조정 전후를 함께 제시. C: 고정비/변동비와 영업 레버리지 가정 |
| FS04 수익성 | ROE 상승이 실제 효율 개선인가요? | 순이익/평균자본, 듀폰 3요소: 순이익률×자산회전율×재무레버리지 | B: 자사주 매입·자본 감소·차입 증가·증자 효과. 분자 이익의 귀속과 분모 자본 범위를 일치시켜 설명 |
| FS05 성장성 | 매출 성장이 이어질 근거가 있나요? | 매출 YoY, 다년 성장 경로, 제공되는 사업부 성장 | B: 고객 집중도·반복매출·수주·신규/기존 고객, 인수·환율 효과. C: 출처가 있는 TAM·침투율·포화 시나리오. 미공시 고객 지표는 추정으로 대체하지 않음 |
| FS06 성장성 | 투자한 돈이 성과로 돌아오나요? | 자산 YoY, CAPEX/매출, 자산회전율, ROIC=NOPAT/평균투하자본 | B: 건설중인자산·가동 시점·투자 성격. C: ROIC−WACC 범위, 투자 회수·수익 전환 기간. WACC는 가정과 기준시점 표시 |
| FS07 현금흐름 | 장부상 이익이 현금으로 들어오나요? | OCF, OCF/순이익, 순이익→OCF 조정 내역 | B: 재고·채권·채무 변화, 비현금 비용, 일시적인 선수금·세금·공급자 금융의 영향. 단일 비율만으로 발생주의 왜곡을 확정하지 않음 |
| FS08 현금흐름 | 배당·자사주 매입을 계속할 여력이 있나요? | FCF=OCF−현금 CAPEX, 배당·자사주 매입, 차입·상환 흐름 | B: 유지/성장 CAPEX, 약정·사용제한·필수 상환 후 여력, 자본배분 이력. 주식보상·증자를 함께 보아 순주식수 변화 확인 |
| FS09 가치평가 | 지금 가격에 어떤 기대가 담겨 있나요? | PER, 보완 PBR·EV/EBITDA, 동종업계·자기 과거 비교 | B: 조정 이익과 보고 이익 차이. C: 이익 성장·할인율·기간을 명시한 역산 시나리오. 하나의 ‘정답 주가’로 단정하지 않음 |
| FS10 가치평가 | 장부가보다 비싸거나 싼 이유는 무엇인가요? | PBR=시가총액/대응 보통주 장부자본, ROE와 추세 | B: 영업권·무형자산·손상·회계상 비용 처리 투자·자산 구성. C: 명시한 가정의 가치평가. 낮은 PBR만으로 재평가 필요·저평가를 확정하지 않음 |
| FS11 리스크 | 재고에 돈이 오래 묶이거나 손실이 날 위험은요? | 재고회전율=매출원가/평균재고, DIO, 재고 증가와 매출·매출원가 변화 | B: 평가손실·제품 수명·재고 구성·계절성. C: 판매 지연·가격 인하·원가 변동 시나리오 |
| FS12 리스크 | 판매한 돈을 제때 회수하고 있나요? | 매출채권회전율=신용매출/평균매출채권, DSO, 채권과 매출 증가 비교 | B: 연령별 채권·대손충당금·고객 집중·매출 인식 주석. 이상 징후와 대체 설명을 제시하고 회계조작으로 단정하지 않음 |

참고자료의 재고회전율 분자는 ‘매출’에서 **매출원가**로 보정한다. 회전율·회수일수는 기초·기말 평균 잔액과 해당 기간의 흐름을 사용한다. 신용매출이 없을 때 총매출 대용 DSO/회전율은 ‘총매출 기준 근사’로 표시한다. CCC의 정의와 평균 잔액 사용은 [CFA Institute의 설명](https://blogs.cfainstitute.org/blog/2013/05/21/a-look-at-the-cash-conversion-cycle/)을 확인했다.

## 3. 오해를 줄이는 표시 규칙

- **부도 가능성 → 재무곤란 위험 신호:** Altman 점수는 채택한 모형·산업·시장·계산일을 표시한다. 원형/변형을 혼합하지 않고 금융업에 일반기업 모형을 적용하지 않는다. 점수를 부도 확률 %로 바꾸는 기능은 별도 보정·검증 전에는 제공하지 않는다. 상세 모형의 계수·적용 범위는 구현 전 원자료 확인을 통과해야 한다.
- **연결/별도와 귀속 일치:** 기본은 연결이다. 연결 전체 순이익에는 전체 평균자본을, 지배주주 이익에는 대응 지배주주 자본을 사용한다. 듀폰 분해는 같은 순이익·매출·자산·자본 범위를 유지한다. 별도 재무제표는 명확히 다른 보기로 제공한다.
- **자본잠식·적자·분모 0:** 음의 자본에서 계산된 ROE/PBR을 우수한 수치처럼 표시하지 않는다. OCF/순이익은 순이익≤0 또는 근접 0이면 비율 판정을 중단하고 금액·추세를 보여준다. PER·EV/EBITDA도 음수 분모를 일반 상대평가에 사용하지 않는다.
- **성장률:** 전년 매출이 양수일 때 YoY를 계산한다. 전기 손실·거의 0인 이익은 ‘흑자 전환’, ‘적자 확대’와 금액 변화로 표현한다. 인수·매각·회계연도 변경 시 단순 성장과 동일조건 성장을 구별한다.
- **차입금과 부채총계 구분:** 기존 `info.debtToEquity`를 부채총계/자본총계와 같은 정의라고 가정하지 않는다. 원문 계정으로 계산하고 이자부차입금 비율은 따로 둔다.
- **FCF 정의 공개:** 기본 CAPEX는 현금으로 지급한 유형·무형자산 취득액으로 정의한다. M&A 현금 지출은 별도 표시하고 투자현금흐름 전체를 CAPEX로 사용하지 않는다. 자산 매각대금을 차감한 순CAPEX 지표를 추가하면 다른 이름을 사용한다.
- **이자·배당·리스 분류:** 보고 OCF와 비교용 조정 OCF를 구별하고 회계기준·적용 연도·선택 정책을 보존한다. 현금흐름에 이미 반영한 지급을 ‘상환 후 여력’에서 또 차감하지 않는다. IAS 7은 현금흐름을 영업/투자/재무로 구분하며 이자·배당 분류 관련 개정도 있어 기준 버전 관리가 필요하다. [IFRS IAS 7](https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/)
- **자사주 효과:** 매입에 따른 현금·자본 감소와 이미 자기주식으로 보유한 주식의 소각을 구별한다. 소각이 항상 자본총계를 추가 감소시킨다고 설명하지 않는다.
- **ROIC/WACC:** NOPAT 산출 세율, 영업 투자자본·초과현금·영업권·리스 포함 정책을 명시한다. WACC의 자본구조·차입비용·무위험수익률·위험프리미엄·기준 통화를 기록하며 값이 없으면 비교를 보류한다.
- **산업별 해석:** 은행·보험·REIT 등은 일반 제조업 부채·재고·현금흐름 기준을 강제하지 않는다. 전용 지표가 지원될 때까지 적용 불가와 이유를 제공한다.
- **비교의 근거:** 현재 `market + theme[0]` 그룹을 그대로 재무 동종업계로 쓰지 않는다. 사업모델·업종·회계 범위·기간이 유사한 peer set을 정의하고, 비교 회사 수와 선택 근거를 공개한다. 5개 미만이면 백분위 등급을 보류한다.

여러 지표와 기간·동종기업을 함께 비교하고 듀폰 분해로 원인을 살피는 방향은 [CFA Institute의 Financial Analysis Techniques](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/financial-analysis-techniques)에서 확인한 원칙과 맞춘다. 위험·성장·현금 창출력을 하나의 종합점수로 압축하는 기능은 첫 버전에 넣지 않는다.

## 4. 쉬운 해석의 예시

아래 수치는 실제 종목 분석이 아닌 **화면 설명용 가상 예제**다.

> **이익은 늘었지만 현금은 덜 들어왔어요.**
> 올해 순이익 100억원, 영업현금흐름 60억원으로 이익의 현금 전환 비율은 0.6배예요.
> 현금흐름표에는 매출채권 증가로 인한 30억원 유출이 나타나요. 판매한 돈을 아직 받지 못한 영향이 있지만, 이것만으로 부실 매출이라고 판단할 수는 없어요.
> **다음 확인:** 연체된 채권과 대손충당금이 늘었는지 주석에서 살펴보세요.

> **ROE 상승의 일부는 자기자본 감소 때문이에요.**
> 순이익이 100억원으로 같아도 평균자본이 1,000억원에서 800억원으로 줄면 ROE는 10%에서 12.5%가 돼요. 매출과 이익 개선 여부, 자사주 거래와 자본변동을 함께 확인해야 해요.

매출채권의 단순 재무상태표 증감과 실제 OCF 조정액은 인수·환산·비현금 변동 때문에 다를 수 있으므로 예시처럼 현금흐름표의 해당 조정 항목에 근거해 설명한다.

각 설명은 최대 3문장 요약과 펼쳐 보는 근거로 구성한다. ‘주의’에는 이유를 붙이고, 정보가 없으면 ‘확인 자료 부족’이라고 한다. 색상만으로 의미를 전달하지 않는다. 지원하지 않는 분석의 빈칸도 임의의 AI 문장으로 채우지 않는다.

## 5. 수집·정규화와 시장별 지원

현재 `refresh_data.py`는 yfinance `info`의 요약 지표, 가격 이력, 일부 분기 영업이익만 수집한다. 전체 손익·재무상태·현금흐름 및 주석 이력이 없어 새 수집 계층이 필요하다. 기존 시세 수집과 재무 공시 수집 주기를 분리한다.

| 시장 | 초기 공급 경로 | 지원 기준 |
|---|---|---|
| 한국 | OpenDART 회사 식별자·공시 목록·단일회사 전체 재무제표, 공시 원문/주석 | 연결 우선, 별도 구분. 분기·누적·정정 보고서와 커스텀 계정 매핑 검증 |
| 미국 | SEC CIK·submissions·companyfacts, 원문 10-K/10-Q 및 해당 해외발행사 보고서 | 표준 태그 외 커스텀·세그먼트·주석은 원문 보완. 회계연도·보고 주기가 회사마다 다름 |
| 홍콩·중국 | 거래소/발행회사 원문 및 이용 가능한 검증된 구조화 공급자 어댑터 | 첫 버전에서 기업별 원문 경로·확보 여부 공개. 자동 표준화는 실제 제공 범위·사용 조건 확인 후 확대 |

OpenDART는 인증키, 연결/별도 구분, 당기와 누적금액을 제공한다. 따라서 단순한 연도별 값 덮어쓰기로 수집하지 않는다. [공식 API 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)

SEC companyfacts는 표준 taxonomy와 회사 전체 범위의 facts를 집계하며 주석·회사별 모든 확장 계정을 자동 완성하지 않는다. `data.sec.gov`는 CORS를 지원하지 않으므로 공시 수집은 요청 시 서버 Worker와 정기 배치에서 수행한다. [SEC API 가이드](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

계획상 기본 수집 순서는 한국·미국의 식별자와 자료가 확인된 기업부터다. 현재 26개 학습 종목 각각에 `ready / partial / not-collected / unsupported / identifier-unresolved / failed` 상태를 만들고 SPCX 등도 실제 발행회사·공시 연결 확인 없이 값을 만들지 않는다. 검색 14,336개 항목이 모두 분석 가능하다고 약속하지 않는다. 중국·홍콩의 완전한 자동 수집 일정은 별도 확보 조사 후 산정한다.

발행회사(`issuerId`: DART corp_code, SEC CIK 등)와 거래 증권(`securityId`: 거래소+티커)을 분리한다. 다중상장·ADR은 같은 재무를 공유하더라도 주식수·ADR 환산·시가총액·보고 통화가 다르다. ticker 문자열만으로 합치지 않는다.

정규화 규칙:

1. `reportedValue`, 원본 단위/scale, 정규화 값, currency, accountingStandard, scope, accountId, dimensional context, 기간 시작·끝, instant/duration을 보존한다.
2. 보고서 발행·접수 시각, 수집 시각, accession/rcept_no, 원문 위치, 정정 전후 version을 저장한다. 최신 정정본 보기와 당시 공개 정보 보기를 구분한다.
3. 누적 현금흐름은 Q2=상반기−Q1, Q3=9개월−상반기, Q4=연간−9개월로 변환하되 동일 회계 범위·정정판·통화·기간에 한해서만 수행한다. 이미 단일 분기인 손익을 다시 차감하지 않는다.
4. TTM은 중복 없는 연속 4분기 흐름을 합한다. 기말 잔액 4개를 더하지 않는다. 평균 잔액은 기간 양 끝 또는 명시된 분기평균 방식으로 계산한다.
5. DSO/DIO/DPO는 대상 기간의 일수를 사용한다. 동일 회사의 보고 주기·계절성을 맞춰 비교한다.
6. 금액은 원 단위 큰 정수·소수에서 정밀도 손실을 막는 표현으로 보존한다. 사용자 화면에서만 억·조 단위로 반올림한다.
7. 결측, 0, 적용 불가, 계산 불가, 출처 충돌을 다른 상태로 관리한다. 지원되는 계정 이름 유사성만으로 임의 매핑하지 않는다.

## 6. 시스템 구성과 AI 해석

```text
DART / SEC / 기타 허용된 공시 자료
  → scripts/financials/ 수집·원문 추출·정규화
  → packages/financial-analysis/ 단일 수식·정책·계산 근거
  → 검증된 FinancialSnapshot + 규칙 기반 쉬운 설명
  → (후속) 공시 근거를 제한한 AI 해석 배치 + 주장 검증
  → 버전별 object storage + 최신 조회 API
  → Stock 재무 화면 (정적 JSON은 오프라인·fallback)
  → 명시적 가정 변환 → Simulation Lab의 별도 기업 시나리오
```

수식은 순수 계산 패키지가 소유하고 Python/브라우저/AI에서 같은 지표를 제각각 재계산하지 않는다. Node 배치와 UI가 같은 계산 결과·방법론 버전을 사용한다. 기존 5축 점수는 이번 재무 12항목과 별도로 유지하되 중복 지표는 정의 차이를 표시하고 이후 한 정의로 정리한다.

기본 정규 지표 schema는 `metricId`, `value`, `unit`, `period`, `formulaVersion`, `inputFactIds`, `calculationStatus`, `reasonCodes`, `comparisonBasis`다. 해석 schema는 `headline`, `facts[]`, `interpretations[]`, `assumptions[]`, `unknowns[]`, `sourceRefs[]`, `dataVersion`, `analysisVersion`이다. 데이터 충실도·출처 등급과 부도/수익 확률은 다른 값이다.

AI 심화 해석은 첫 데이터·화면 릴리스 다음 단계로 둔다. 첫 릴리스에도 규칙 기반 한국어 설명을 제공하여 ‘알기 쉬움’을 미루지 않는다. 모델 호출 키는 정적 프런트엔드에 두지 않고 CI/서버의 비밀 저장소에서 사용한다. 문서가 변경된 회사만 재생성하고 입력/프롬프트/모델/출력 버전으로 캐시한다.

AI에는 해당 회사·보고 기간의 검증한 수치와 지정한 공시 발췌만 전달한다. 원문 내 지시문은 명령이 아닌 자료로 취급한다. 모델이 수치를 새로 만들거나 잘못된 회사/기간을 참조하면 해석 게시를 중단한다. 문장별 fact ID·주석 위치·증거 유형을 연결하고 존재하지 않는 source ID를 거부한다. 원인 설명은 사실과 추론을 구분하고 대체 설명·미확인 내용을 포함한다.

일회성 항목 조정은 조정액·원문·반복 여부·조정 이유를 공개하며 AI가 모든 비현금 비용이나 주식보상을 자동으로 제거하지 않는다. 고객 집중도·TAM·미사용 신용한도·만기 분포가 없으면 해당 분석을 보류한다. 재무 위험·회계 이상 탐지는 점검 대상을 설명하며 법적 위반·회계부정 사실을 생성하지 않는다.

## 7. 시뮬레이션 랩과 연결

관심 기업의 실제 재무 스냅샷을 복사해 **기업 유동성·수익성 시나리오**를 만든다. 현재 InfraWheel의 글로벌 산업 매출·CAPEX에 회사 재무를 직접 대입하지 않는다. 기업 모델은 `corporate-finance-v1`이라는 별도 modelId로 등록하고 분기 4개부터 지원한다.

첫 연결 후보는 매출·마진 변화, 금리 변화, 채권 회수 15일 지연, 재고 보유 20일 증가, CAPEX 조정이다. 금리는 변동금리 차입·재조달 대상에만 반영하고 고정금리 전체 차입에 즉시 적용하지 않는다. 운전자본 변화는 현금으로 변환해 한 번 반영하며 OCF와 중복 차감하지 않는다. 필수 상환·차환·한도·현금 제한 조건이 없으면 ‘해당 조건 제외’가 아니라 ‘계산에 필요한 자료 부족’ 상태로 결과의 지원 범위를 표시한다.

결과는 시나리오별 기말 현금, 필요한 조달 금액, 이자 부담, 주주환원 후 잔액을 보여준다. 이는 가정하의 자금 계산이며 부도 확률·미래 주가가 아니다. 월별 만기 위기 분석은 월별 지급 일정과 모델 검증을 추가한 후 지원한다. 분기 자료를 균등 3분할해 정밀한 월별 전망처럼 표현하지 않는다.

| 검증 영역 | 반드시 확인할 사례 |

| 심화 | 듀폰 항등식과 자사주 예제, OCF/순이익 왜곡, FCF·이자·배당·리스의 중복 차감 없음 |
| AI | 회사·기간·숫자·출처 불일치 0, 미공시 TAM/고객/만기 생성 거부, 일회성 제거 근거, 위험 확률·부정 단정 억제 |

V1 완료는 지원 대상으로 선언한 회사의 3개 주요 재무제표 표와 확보된 추세, 12개 질문의 계산/미지원 상태, 쉬운 설명과 출처가 함께 동작하는 것이다. 단순히 지표 카드 12개가 보이는 것을 완료로 보지 않는다. API 키·실제 자료 확보가 되지 않은 부분은 fixture 통과와 실데이터 통과를 구분한다.

AI 출시는 사전 고정한 다양한 재무 사례 세트에서 숫자·회사·기간·출처의 중요 오류가 없고, 설명의 근거와 반례를 검토한 후에 한다. 정확한 문자열 인용이 있다고 해서 해석도 옳다고 자동 판단하지 않는다. 실패 시 검증된 규칙 기반 설명으로 대체한다.

## 9. 작업·순서·추가 일정

아래는 1명 순차 개발 기준의 추가 작업일 추정이며 실제 데이터 확보 대기는 별도다. 지원 시장·발행회사 범위의 요청 시 수집 API는 FR0에 포함한다. 중국·홍콩 전체 자동 표준화와 금융업 전용 지표는 별도 후속 범위다.

| 단계 | 작업일 | 내용 |
|---|---:|---|
| FR0 최신 조회 서비스 | 5–8 | 요청 시 수집 API·작업 큐·스케줄러·시세 어댑터·최신성 상태 |
| FR1 재무 기반·쉬운 화면 | 15–22 | 회사 식별·지원 목록, 한국/미국 수집, 3표 정규화, 12개 질문·계산 상태·규칙 설명, 관심 종목 진입·검증 |
| FR2 공시 근거 AI 심화 | 7–10 | 주석·만기·일회성·고객 정보 추출, 근거 연결, 조정 내역, 분석 캐시·오류 차단·평가 |
| FR3 기업 시나리오 연결 | 4–6 | 별도 기업 모델·버전 고정 스냅샷, 금리·회수·CAPEX 가정, 랩 연결·회귀 |
| 재무 기능 추가 합계 | **31–46** | 데이터 조회 → 근거 있는 해석 → 가정 실험 |

우선 실행 순서는 **공통 식별·데이터 계약 → FR0+FR1 출시 → 랩의 기존 P0–P3 진행 → FR2 → 기업 모델 계약 확정 후 FR3**다. P4/P5의 산업 보정·불확실성 분석은 기존 계획대로 별도 검증한다. FR1은 랩 전체 구현을 선행 조건으로 두지 않는다.

기존 산업 랩 전체 36–53일에 재무 추가를 단순 합산하면 **67–99 작업일**이다. 최신 조회 API·재무 조회·쉬운 설명을 우선 출시하는 범위는 FR0+FR1 20–30일이며, AI 심화·기업 시뮬레이션을 그 기간에 포함한다고 해석하지 않는다. 상세 작업 ID는 [백로그의 FR 섹션](simulation-lab-backlog.md)에 있다.

## 10. 확인 범위

이번에는 기존 소스와 계획을 읽고 OpenDART·SEC·CFA Institute·IFRS 공식 공개 자료를 확인하여 요구사항·데이터·계산·해석·검증·일정을 계획에 반영했다. 특정 관심 기업의 실제 공시 수집, 지표 계산, 신용 판단, 앱 구현은 수행하지 않았다. Altman 원문 PDF는 이번 접근에서 열리지 않아 구체 계수·지역별 성능·확률 전환을 확정하지 않았다.
